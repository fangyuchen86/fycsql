# Native Go API, Opt-In database/sql Driver, Context Boundaries, and Structured Error Taxonomy

fycsql v1 exposes a first-class native Go API in the root `fycsql` package (`Open`, `DB`, `Conn`, `Tx`, `Stmt`, `Rows`, `Result`, functional `Option`s, `View`/`Update` helpers, and `NewConnector` for `sql.OpenDB`) alongside a thin `database/sql/driver` adapter whose global `sql.Register("fycsql", ...)` lives in an opt-in `fycsql/driver` subpackage. Each `Open` or `NewConnector` owns its underlying engine 1:1 (including isolated private `MemFS` instances for `:memory:` and `ErrDatabaseLocked` on duplicate same-process file opens), while all pooled `driver.Conn` handles inside a single `*sql.DB` share the `Connector`'s engine without `SetMaxOpenConns(1)` bottlenecks. Cancellation follows three strict boundaries (statement `stmtCtx` discards only its Statement Delta; transaction `txCtx` aborts the Transaction; the Commit Gate honors `ctx` until WAL append begins, never abandoning an in-flight `Sync()`), errors surface via structured `*fycsql.Error` with multi-error `Unwrap() []error` sentinel matching, and `CloseContext(ctx)` / `Close()` drains cleanly with `CheckpointTruncate` while preserving `<db>-wal` on drain timeout or Fail-Stop.

## Considered Options

- **Exposing Only `database/sql` Without a Native Go API**: Minimizes public surface, but forces reflection-based scanning, hides zero-copy row access, lacks idiomatic OCC retry helpers (`Update`), and requires custom SQL `PRAGMA` statements to invoke operational controls like `Checkpoint` and `Verify`.
- **Registering `database/sql` in Root Package `init()`**: Saves one import path, but forces global `database/sql` registration side effects onto native-only callers and couples root `fycsql` to `database/sql`'s pool package.
- **Accepting `sql.LevelSerializable` / `time.Time` Silently in `database/sql/driver`**: Maximizes naive drop-in compatibility, but misleads callers about v1's Snapshot Isolation write-skew boundary (ADR-0001) and contradicts v1's strict 5-type system with no native timestamp type (ADR-0002).
- **Process-Wide Ref-Counted Path / Shared `:memory:` Registry**: Allows multiple `Open` calls on the same path to share one engine, but obscures close/checkpoint ownership and creates cross-test contamination hazards.

## Consequences

- **Dual-surface ergonomics & explicit session boundary**: Native `Rows.Scan` safe-copies `[]byte` by default while exposing opt-in borrowed zero-copy access (`RawBytes` / `Values()`, valid until next `Next()`/`Close()`). Stateless `*DB` and pooled `*sql.DB` reject raw SQL `BEGIN`/`COMMIT`/`ROLLBACK` and multi-statement strings (`ErrSyntax`), while stateful `db.Conn(ctx)` supports SQL transaction statements for CLI and `sqllogictest` runners; `Connector.DB()` gives `sql.OpenDB` callers direct typed access to `Checkpoint` and `Verify`.
- **Honest, deadlock-free `database/sql/driver` contract**: `Connector` implements `io.Closer`; `driver.Conn` implements `SessionResetter`, `Validator`, `Pinger`, `ConnBeginTx`, `ConnPrepareContext`, `ExecerContext`, `QueryerContext`, and `NamedValueChecker` (accepting `uint64 <= math.MaxInt64` and finite floats, rejecting `time.Time` and `NaN`/`±Inf`); `driver.Rows` checks query `ctx.Err()` in `Next()` and implements `RowsColumnTypeScanType`/`DatabaseTypeName`/`Nullable`. `ConnBeginTx` accepts `LevelDefault`, `LevelSnapshot`, and `LevelRepeatableRead`, strictly rejecting all other isolation levels and enforcing `opts.ReadOnly`; DSN URIs (`file:<path>?...`) reject unknown parameters loudly.
- **Retryable OCC & clear `Result` semantics**: `DB.Update` auto-retries `IsRetryable(err)` (`ErrConflict` / `ErrSchemaChanged`) up to `MaxUpdateRetries` (default `5`, jittered exponential backoff within `ctx`) with documented idempotency; `LastInsertId()` returns the `int64` Row Key for single-column `INTEGER` PKs and hidden Internal RowIDs, and `(0, ErrNoLastInsertId)` for composite/non-integer PKs or non-`INSERT` statements.
- **Hierarchical sentinel errors via `Unwrap() []error`**: `*fycsql.Error` carries `{Code, Op, Message, Table, Constraint, Line, Col}` and unwraps to canonical sentinels (`ErrConflict`, `ErrSchemaChanged`, `ErrTxTooLarge`, `ErrTxDone`, `ErrReadOnly`, `ErrSyntax`, `ErrConstraint` + `ErrUniqueViolation`/`ErrNotNullViolation`/`ErrPrimaryKeyViolation`, `ErrTypeMismatch`, `ErrOverflow`, `ErrDivisionByZero`, `ErrInvalidFloat`, `ErrNotFound`, `ErrNoRows`, `ErrNoLastInsertId`, `ErrDatabaseLocked`, `ErrDatabaseClosed`, `ErrCloseTimeout`, `ErrCorruption`, `ErrIO`, `ErrFailStop`, `ErrCommitIndeterminate`).
- **Shutdown and read-only opens.** Closing stops admission and drains work. On timeout, cancel logical handles and return `ErrCloseTimeout` in a closing state. The engine retains descriptors and its process lock until all physical reads, commits and Checkpoints exit, then releases them. Timeout and Fail-Stop preserve the WAL. Successful close uses ADR-0004’s full-backfill condition. Read-only opens hold the lock, scan both files through read-only descriptors, reject mutations with `ErrReadOnly` and preserve both files on close.
- **Queue cancellation and uncertain results.** Cancellation can withdraw a queued request up to the atomic transition to WAL append. Once append starts, return its actual outcome. Complete each caller when its own batch finishes even if the queue stays busy. An uncertain append or commit sync returns `ErrCommitIndeterminate` with the I/O cause. Subsequent writes return `ErrFailStop`. Both the driver and native helpers prohibit replay of an indeterminate statement, including via `driver.ErrBadConn`.
